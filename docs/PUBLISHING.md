# Публикация и передача владельцу Zarya

## GitHub

Исходники публикуются отдельным репозиторием. GitHub хранит код; для сетевой игры нужен работающий Node.js-сервер. GitHub Pages не заменяет этот сервер.

Если репозиторий создаётся вручную, создайте пустой репозиторий `battle-for-rokugan-boardgame` без README, лицензии и .gitignore. В PowerShell из папки проекта:

```powershell
git remote add origin https://github.com/OWNER/battle-for-rokugan-boardgame.git
git push -u origin HEAD:main
```

Замените `OWNER` на свой логин. Если `origin` уже настроен, проверьте его командой `git remote -v`, повторно добавлять его не нужно. Git может открыть вход в браузере. Пароли и токены не добавляйте в команды или файлы проекта.

## Что передать владельцу сайта

- Ссылку на GitHub-репозиторий и идентификатор коммита (`git rev-parse HEAD`). Для приватного репозитория владельцу нужен доступ.
- [Инструкцию интеграции](SITE-INTEGRATION.md), включая маршруты API и переменные окружения.
- `zarya-game.json` — предлагаемую запись каталога, а не файл автоматического импорта.
- `Dockerfile`, `compose.yaml`, `.env.example` и `deploy.sh`.

Владелец регистрирует игру `rokugan` / `battle-for-rokugan` в закрытом репозитории платформы, согласует поддомен, подключает proxy с WebSocket, постоянное хранилище матчей и общий серверный секрет. Затем добавляет игру в каталог и канал. Предлагаемый адрес `https://rokugan.zarya-boardgames.ru` ещё не является опубликованной игрой.

До выкладки:

```sh
npm ci
npm test
npm run build
npm run test:platform
docker compose build
```

Docker-сборку нужно проверить на машине с Docker. В среде подготовки Docker отсутствует.

После выкладки: проверить `/health`, создать комнату на сайте, войти двумя аккаунтами, начать партию, переподключиться и проверить выход через платформу. Не удалять volume матчей при обновлении.

Merge request на добавление игры создаётся в репозитории платформы после предоставления доступа к нему; создание отдельного репозитория игры само по себе не добавляет её на сайт.
