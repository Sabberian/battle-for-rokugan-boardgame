# Подключение к Zarya Boardgames

## Что установлено по открытым источникам

Проверено 9 ноября 2026 года:

- Сайт: https://zarya-boardgames.ru/ — игры открываются в iframe на отдельных поддоменах.
- Публичный каталог: https://zarya-boardgames.ru/api/public/showcase — поля `id`, `title`, `bgioName`, `minPlayers`, `maxPlayers`, `publicUrl`, `channelName`.
- Пример интеграции: https://github.com/Stanislavecddpb/ghost-fight-boardgame/blob/main/packages/server/src/platform.ts
- Пример выкладки: https://github.com/Stanislavecddpb/panic-station-boardgame/blob/main/deploy.sh — вызывает `deploy/game.sh HOST gameId` из соседнего `zarya-boardgames-platform`.
- Публичного репозитория `Stanislavecddpb/zarya-boardgames-platform` не найдено: GitHub API возвращает 404. В опубликованном клиенте не найден пользовательский импорт ZIP или GitHub-проекта. Это не исключает отдельного закрытого инструмента администратора.

`zarya-game.json` повторяет наблюдаемые поля каталога. Это подготовленная запись для владельца платформы, **не подтверждённый формат автоматического загрузчика**. Адрес `https://rokugan.zarya-boardgames.ru` предложен для новой игры; DNS и сервис ещё не созданы.

## Передать владельцу сайта

1. Исходники этого проекта как отдельный Git-репозиторий либо архив.
2. `zarya-game.json` — запись каталога, согласовать `id=rokugan` и адрес.
3. `Dockerfile`, `compose.yaml`, `.env.example` — сборка и запуск.
4. Этот документ с контрактом API.

В закрытом репозитории платформы владельцу нужно зарегистрировать игру, её внутренний адрес и общий секрет, добавить канал и маршрут поддомена. Точные имена внутренних полей и файлов неизвестны без исходников платформы. В опубликованном клиенте иллюстрации/описания каталога связаны с ID игр: для `rokugan` также следует добавить оформление карточки, используя `/art/cover.webp` этой игры.

## Запуск сервиса

Node.js 22+, одна служба для HTML, API и Socket.IO:

```sh
npm ci --include=dev
npm run build
npm start
```

На Windows: `npm.cmd` вместо `npm`. Скрипт `npm run play` собирает и запускает игру. Переменные окружения хостинг передаёт процессу; `.env` сам по себе не загружается командой `npm start`. Для прямого запуска с файлом: `node --env-file=.env build/server/src/index.js`.

Docker: скопировать `.env.example` в `.env`, указать реальный `PUBLIC_URL` и сгенерированный `PLATFORM_SECRET`, затем:

```sh
docker compose up -d --build
```

Compose публикует игру на `127.0.0.1:3017`; порт можно изменить. Reverse proxy должен направить HTTPS-поддомен на этот порт, включая WebSocket Upgrade для `/socket.io/`. Если игру включают в общий Docker Compose платформы, её backend может обращаться по внутреннему адресу `http://rokugan:3001`; оба сервиса должны быть в общей сети. Не перезаписывайте общий Compose этим самостоятельным примером.

`MATCHES_DIR=/app/data/matches` хранится в постоянном named volume. Сохраняйте его при обновлениях. Docker запускает приложение от пользователя `node`; для собственного bind mount нужно обеспечить ему запись.

- `PUBLIC_URL`: публичный origin игры; автоматически добавляется в CORS.
- `ALLOWED_ORIGINS`: дополнительные origins через запятую, если нужны.
- `PLATFORM_SECRET`: одинаковый секрет на backend платформы и backend игры. Не помещать в URL, клиентский JavaScript или Git.
- `PORT`: внутренний HTTP-порт, по умолчанию 3001.
- `VITE_SERVER`: необязательный адрес отдельного backend при сборке клиента. Для обычного размещения не нужен.
- `GET /health`: `{ "ok": true, "game": "battle-for-rokugan", "status": "ready" }`.

## Контракт платформы

В API boardgame.io зарегистрирована только полноценная игра `battle-for-rokugan` (2–5 игроков), без лабораторного режима.

| Действие | Маршрут |
|---|---|
| Создание комнаты | `POST /games/battle-for-rokugan/create`, JSON `{ "numPlayers": 4 }` |
| Список комнат | `GET /games/battle-for-rokugan` |
| Места комнаты | `GET /games/battle-for-rokugan/:matchID` |
| Занять место | `POST /games/battle-for-rokugan/:matchID/join`, JSON `{ "playerID": "0", "playerName": "Имя" }` |
| Клиент игрока | `/?name=Имя&embed=1#/m/:matchID` (имя URL-encode) |
| Зритель | `/?embed=1#/m/:matchID/watch` |
| Освободить место с платформы | `POST /platform/matches/:matchID/leave`, JSON `{ "playerName": "Имя" }` |
| Удалить комнату с платформы | `DELETE /platform/matches/:matchID` |

Оба `/platform`-маршрута требуют `x-platform-secret` и включаются только при заданном секрете. Вызовы делает backend платформы, а не браузер. Освобождение места удаляет credentials; клиент замечает освобождение при обновлении списка и возвращает экран выбора места. Удаление комнаты — безвозвратно, поэтому платформа должна применять своё обычное подтверждение/правило удаления пустых столов.

`embed=1` убирает навигацию и приглашения самой игры, а также выход из внутреннего лобби: ссылку и действие «Встать из-за стола» предоставляет Zarya. Игрок выбирает место, затем клан; хозяин запускает игру после подключения всех. Отдельной кнопки готовности нет. Секретные руки и цели скрываются на сервере, в том числе от зрителей.

## Проверки до передачи

```sh
npm test
npm run build
npm run test:platform
```

Последний тест поднимает отдельный локальный сервер и собственную временную базу: проверяет регистрацию игры, CORS, 4 места, старт хозяином, сохранение после перезапуска, освобождение/повторный вход и удаление с секретом. Он не обращается к живому сайту.

Docker CLI на машине подготовки недоступен: контейнер здесь не запускался. Сборка и сервер проверены непосредственно на Node.js; перед выкладкой владелец должен собрать контейнер в своей среде.

## Обновления через существующий механизм

После регистрации `rokugan` в закрытой платформе и коммита исходников можно использовать подготовленный `deploy.sh`, повторяющий обёртку Panic Station:

```sh
HOST=user@your-server PLATFORM_DIR=../zarya-boardgames-platform bash deploy.sh
```

Он требует закрытый `deploy/game.sh` и зарегистрированный ID `rokugan`. Это помощник для последующих обновлений, не самостоятельный импортёр. Сервер сайта в ходе подготовки не изменялся.
